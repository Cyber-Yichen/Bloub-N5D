# 0.9.2 验证记录

日期：2026-10-12。设备为 N5D，Android 11 / API 30。所有现场图片、录像、设备地址、访问码与测试脚本保留在本地忽略目录，不提交公开仓库。

## 构建与逻辑测试

- 前端 18 个测试文件、237 项通过；Vue/TypeScript 类型检查与 Vite 构建通过。
- Java 核心 254 项通过：工位学习与漂移 33，存储/签名/XMP/WebDAV 120，曝光/迁移/OSS V4 16，0.9.2 新增边界 67，夜间规则 18。
- 新增测试覆盖六位访问码、单个 HTTP Range、照片/监控互斥、保留范围、观察新鲜期、变化窗口合并/裁剪及局部画面变化。OSS/COS 的 PUT/DELETE 向量独立对照官方 Python SDK，包含中文路径和临时令牌。
- 固定模型与运行时通过 SHA256 校验，下载入口可复用；APK 通过 zipalign 与 v2/v3 签名验证。MediaPipe 要求 minSdk 24；本机开发证书不提交。

可复现命令：`pnpm test`、`python3 android/fetch-dependencies.py`、`bash android/test/run.sh`、`bash android/build.sh`。Java 测试依赖 JDK 和 `libandroid-json-java`，可用 JSON_JAR 指定 jar。

## 图库性能

同机相邻数据集测量：旧版 721 张照片，五次列表为 907/907/856/878/872 ms；新版 733 张，737/98/70/84/72 ms。新版首次读取仍需要建立索引，后续读取复用索引。

96 张缩略图批量旧版耗时 55.7 秒、约 1.62 MB；新版 0.48 秒、约 0.44 MB。数据集与缓存状态并非严格相同，该结果用于确认现有瓶颈改善，不是对任意网络的性能保证。修复包括缩略图生成、缓存、列表索引、六个 HTTP worker 和浏览器过时请求取消。

## 实机模型与录像

- 面部、手部、全身模型在真实相机流中均成功加载并运行；当时办公室较暗且无正面人物，不将零结果当作识别准确率证明。
- 独立测试应用使用官方 `portrait.jpg`、`right_hands.jpg`、`male_full_height_hands.jpg` 正样本，设备分别输出 478 面部点、两只手各 21 点、全身 33 点和面部/双手点；几何覆盖图已查看。测试应用已移除，样本没有写入工位学习与图库。
- 官方 Holistic 发布二进制需要完整 Protobuf Any.Builder ABI；从 javalite 更换为固定完整 Protobuf Java 4.26.1 后通过验证。
- 实际相机录制 MP4 包含 H.264 1280×960、约 29.6 fps 和 AAC 16 kHz 单声道；15 秒分段实际音视频时长约 14.8/15.0 秒。时间戳与声音类别实际烧录到视频，已解码检查。
- 独立定位图录制验证四种附加旋转和镜像，几何点与画面一致变换，HUD 保持正常朝向。渲染给 MediaRecorder 保留绝对源帧时间戳，避免该设备编码器丢弃相对零时间帧。
- 实际带全部叠加、镜像和附加 90° 的录像输出为 960×1280、约 29.6 fps；检测标签在最终图层保持可读，框与画面一同变换。
- HTTP 视频范围读取验证 206、指定字节数量与非法范围 416。录像分段仍存在短暂重建间隔；非无缝连续录像。

- 实际浏览器验证分页、页数、每页数量、旧请求取消、五个页面、缩略图 ETag/304、访问码刷新与自定义、旧码 401、保留天数修改和不合法类型 400。

- S3 连接测试在设备发出真实 HTTP PUT/DELETE，由独立模拟服务校验方法、请求体摘要与 SigV4；验证草稿不保存、使用已存凭证、403 写入失败和删除失败说明。

## 数据与功能边界

关键点仅用于实时/录像叠加，不做人脸身份识别、情绪推断、工位身份学习或新增宠物交互。照片工位标签仍是模型估计，不是人工真值。夜间无人、画面不可用等情况不会伪造有人/无人统计。

实机静止画面产生两段私有滚动缓冲、零个公开变化片段；每日上传测试确认设定时间前不上传，时间到后发送 MP4 与 JSON。变化窗口合并、裁剪及局部画面变化纯逻辑已验证；首次启动及主动停止录像无法补出未录制的前后帧。云端版本策略不由测试按钮更改。待上传片段保留至成功或人工删除，容量达到预算会暂停录像。短时实测不能保证所有办公室光线、连续运行时长和网络环境下的识别或存储效果。
